## 从收到停产通知到关单

电子产品、工控设备及维修支持团队收到制造商停产通知后，需要在末次订购期限前决定：买多少、是否已验证替代料、还是终止对应产品。EndFlow 把原始通知、受影响产品需求、独立分配的库存与在途、批准数量和实际收货凭证连到一份记录中。

适用于一个组织内部的工程、供应链、采购及独立复核岗位。其价值是保存可核对的决策基线、及时暴露订购逾期、避免超过批准数量重复登记收货，方便事后查询与交接。

**它是人工协作台账。** 不读取邮件或供应商网站，不自动展开 BOM，不连接 ERP/WMS，不向供应商下单，不产生银行支付，不验证替代元件的电气兼容性。通知日期与规则以对应制造商原始文件为准；库存分配由团队先在实际库存系统核对，台账自身不锁定实物库存。

### 三条可操作路线

| 路线 | 状态与人员 |
| --- | --- |
| 末次采购 | 编制草稿 → 提交复核 → 独立批准冻结 → 指定采购员登记今日订单 → 分批收货登记 → 独立核验关闭 |
| 替代料切换 | 填写不同的候选替代料及验证报告编号 → 独立批准冻结 → 指定采购员登记实际工程变更实施凭证 → 独立核验关闭 |
| 产品退役 | 需求和退役依据 → 独立批准冻结 → 登记实际退役实施凭证 → 独立核验关闭 |

待复核可退回草稿；待复核或已批准、尚未执行的决策可独立取消。下单后不能通过取消消除履约记录。已关闭的通知禁止修改和冲正。

### 数量如何得到

每条产品用途按个数核算：

```text
支持期需求 = 月需求 × 支持月数 + 售后保留需求
用途缺口 = max(0, 支持期需求 - 独立分配库存 - 独立分配在途)
总缺口 = 各用途缺口之和
采购建议 = 总缺口为零时为零；否则取 max(总缺口, 最小订购量) 后按包装倍数向上取整
申请金额 = 申请数量 × 单价，以人民币元保留两位小数
```

不同用途的多余库存不抵扣其他用途，防止未经重新分配的供给被重复计算。申请数量必须覆盖建议、最小订购量和包装倍数，金额不得超通知预算。超过建议量的业务理由保存在决策依据中，由独立复核员判断。系统不预测市场需求、不保证数据真实，不支持混合单位、外币与税务计算。

## 业务端与管理端

| 模块 | 已实现能力 |
| --- | --- |
| 我的工作台 | 本人参与的未结通知与路线、状态、期限 |
| 停产通知 | 一份通知一个制造商料号，来源凭证、日期、岗位、预算和处置路线；搜索、状态筛选、三种排序、分页 |
| 需求快照 | 产品用途、支持周期、保留需求、独立分配库存/在途与证据；草稿增删改查，提交冻结 |
| 复核决策 | 编制与复核独立；采购与复核独立；提交、批准、退回、取消 |
| 实际履约 | 今日订单登记、承诺交货期限、分批收货、超量防护、独立冲正留存、实施凭证、关闭 |
| 统计与导出 | 范围内状态分布、未下单订购逾期、已批准采购金额、原始业务 JSON 导出 |
| 系统管理 | 账号、部门、角色、权限名称、导航名称/权限/顺序、字典、系统参数；内建资源和最后全范围管理员保护 |
| 安全与追踪 | BCrypt 12、同源会话、CSRF、即时权限复核、ALL/DEPARTMENT/SELF、状态版本、UUID精确重试、业务事件与操作审计 |
| 关于系统 | 版本、公司、官网、许可定位、原始联系二维码和前端第三方许可 |

管理员维护岗位与部门；业务人员使用同一响应式页面，菜单来自实时角色。SELF 仅能查看同部门内本人编制、采购或复核的通知；获知编号也不能越权读取详情和导出。具备操作权限仍必须是指定人员，管理员没有绕过指派的业务捷径。

每份通知最多 100 条需求、200 笔原始收货登记（包括已冲正）；总通知上限默认 1000，可在系统参数内设置 100–1000。管理目录最多 10000 行；操作审计展示范围内最近 500 行。通知事件在整份详情中保留。所有数量必须是整数，建议量及申请量上限十亿个，支持周期最多 120 月。

## 空库启动

需要 Python 3、Docker Engine／Desktop 和 Compose v2，首次构建需要访问官方镜像及公开依赖仓库；源码开发另需上表中的 Java、Maven、Node 和 MySQL。

```bash
python3 scripts/init-env.py
# .env 生成独立强随机密码，文件权限0600，默认仅绑定本机。
docker compose config --quiet
docker compose up -d --build --wait
```

浏览器访问 **[http://127.0.0.1:8120/](http://127.0.0.1:8120/)**。管理员账号 `admin`，初始密码读取本机 `.env` 的 `ADMIN_PASSWORD`。没有硬编码通用演示密码。初始化只创建总部、四类岗位、权限菜单、类别与参数，不伪造通知或采购记录。已有数据库重启不会重置密码或覆盖数据。

管理员先创建部门和需求编制员、采购执行员、独立复核员账号。复核员必须与编制员和采购员不同；人员属于通知部门并具备对应权限。操作顺序见 [使用手册](docs/操作手册.md)。

| 配置 | 含义 |
| --- | --- |
| `DATABASE_PASSWORD` | 应用数据库用户密码；必须设置 |
| `MYSQL_ROOT_PASSWORD` | MySQL初始化密码；必须设置 |
| `ADMIN_PASSWORD` | 仅空库创建管理员使用；至少12位含大小写字母和数字，最多72字节 |
| `WEB_PORT` | 页面端口，默认8120；冲突时修改为可用端口再启动 |
| `BIND_ADDRESS` | 默认127.0.0.1；正式入口须由部署方配置HTTPS代理与访问控制 |
| `COOKIE_SECURE` | 本机HTTP为false；HTTPS环境设true |
| `DATABASE_URL` / `DATABASE_USER` / `DATABASE_CATALOG` | 后端独立连接现有MySQL时可覆盖，目录与实际数据库名称一致 |

数据库不发布主机端口。健康入口 [http://127.0.0.1:8120/actuator/health](http://127.0.0.1:8120/actuator/health)；仅暴露 health。Compose 三个服务均使用健康检查并按顺序等待。

### 数据与升级

完整建表脚本：[V1身份目录](backend/src/main/resources/db/migration/V1__identity.sql)、[V2停产业务](backend/src/main/resources/db/migration/V2__eol.sql)。业务表包括 `eol_case`、`demand_line`、`receipt`、`case_event` 和 `command_record`。外键保护账号、部门与历史，通知编号、用途编码和收货凭证有唯一约束。应用写入与管理员变更共享总部锁，锁后刷新身份权限，在 READ COMMITTED 下检查版本与UUID；实现面向小团队并发，不承诺大吞吐。

升级前备份数据库与 `.env`，先在备份副本上运行新版本。不能更改已执行迁移的正文；后续升级添加更高版本。只在备份可恢复且迁移和健康检查成功后切换服务。`docker compose down` 保留数据库；`down -v` 会删除数据，正式数据禁止直接执行。具体部署与恢复见 [部署手册](docs/部署手册.md)。

## 常见问题与运行边界

- 启动失败：查看 `docker compose logs --tail=100 backend mysql`，核对版本、配置和健康；不要用跳过测试或删除正式卷处理。
- 登录失败：空库密码来自 `.env`；已有库以最后设置为准。失败达到8次时账号5分钟限制登录。修改密码后重新登录。
- 找不到记录：确认账号启用、所属部门、数据范围和本人指派；菜单可见不代表拥有每笔业务的操作权。
- 提交失败：核对需求快照、包装倍数、预算与末次订购日期；替代路线需要独立核对过的验证报告，数量为零。
- 版本冲突：刷新详情后重新核对内容再提交；相同UUID不能用于不同请求载荷。
- 收货错误：由指定独立复核员在关单前冲正，再按新凭证登记。冲正是更正台账，不是实物退货或财务退款。
- 截止日已过：保留通知事实，可退回重新评估路线或取消未执行决策；不得修改日期掩盖已执行事实。
- 原始交货迟到：可登记订单日至今日之间的真实收货事实；承诺日期不会变为实际日期，迟到不能被软件自动免除。

会话 Cookie 为 HttpOnly/SameSite=Strict，CSRF默认开启；账号停用、权限撤回、密码变化在接口重新校验。仅支持同源单组织应用，不提供多租户、SSO、邮件通知、文件附件、自动采购、预测模型或自动备份。部署方负责HTTPS、访问隔离、备份恢复及真实数据核验。

软件保存人工输入的协作记录，不替代工程验证、合同审核或实物库存控制，不保证供应商供货、采购决策正确或替代元件安全兼容。
