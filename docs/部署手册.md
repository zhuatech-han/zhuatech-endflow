# EndFlow 部署与数据恢复

推荐DockerComposev2和BuildKit，默认127.0.0.1:8120，只给本机提供入口；MySQL和后端没有发布主机端口。init-env.py生成0600配置；必需数据库和管理员密码不写入Git。构建前compose config --quiet，构建Maven不能跳过测试，镜像非root运行。

修改WEB_PORT后重新创建前端即可覆盖冲突端口。已有库ADMIN_PASSWORD不会重置账户。只在HTTPS代理后使用COOKIE_SECURE=true；生产接入前核实受信代理、外部访问规则、数据用途与商业书面授权。

## 升级

1. 保存当前镜像版本、数据库和.env的安全副本。
2. MySQL官方mysqldump对单独数据库做一致性备份，凭证使用受控配置而非公开日志或源码。
3. 将备份恢复到独立测试库，检查V1/V2记录和所有新迁移，跑业务与权限验收。
4. 重新构建并启动服务，检查三个健康状态，Flyway历史与实际业务数量。
5. 失败时停止写入并恢复已验证备份，避免对已升级库直接运行旧代码。

首次启动只能在空库验收；迁移完整SQL位于backend/src/main/resources/db/migration。已执行迁移正文不得修改；后续使用新版本号。Flyway已执行迁移的重启应校验并保持数据。

## 本地验收资源

使用独立项目名endflow-check和全新mysql-data卷，切勿误用正式数据库。smoke.py创建TEST数据与本机临时凭证；--verify用于后端重启后核对持久化。结束仅清理这套隔离容器、网络和卷。一般停止docker compose down保留数据；不要对正式环境执行down -v或全局prune。

本版本无自动备份、集群、跨机房恢复及云配置，部署方应完成备份还原演练与访问监控。
