# EndFlow 架构与事务

单组织的Vue应用由Nginx托管；同源/api代理到Spring Boot，JPA访问MySQL8.4，Flyway执行V1身份和V2业务。公开REST入口由Spring Security保护，匿名仅健康、CSRF和登录。

## 数据职责

- eol_case：唯一编号、制造商料号、三类日期、三岗位、固定决策与预算、订单/实施凭证、人工版本号。
- demand_line：唯一通知内产品用途、需求与供给快照，固定整数个数。
- receipt：不可覆盖的原始分批收货；冲正追加标记与理由，不删除原行。
- case_event：业务事件、操作人、前后状态和证据；只能随事务写入。
- command_record：UUID与包含账号、路径动作、完整载荷的SHA256指纹，避免重复登记。
- 身份目录：部门、角色、账号、权限、菜单、字典、参数、操作审计。

所有写事务与管理员变更先锁总部Department1，采用READ_COMMITTED，再刷新当前账号和角色，检查实时权限。业务共享基线的更改由通知版本号保护，UUID处理精确重复；并发不同请求持旧版本时其中一个返回409，同一UUID相同输入只写一次。所有角色与业务外键受数据库约束保护。锁为本机小团队串行写入设计，需高吞吐场景应另行设计分区锁及并发基准。

需求每条独立核算缺口，整合后按最小量及包装倍数上取整。BigDecimal计算成本，数量用long中间值防溢出；预算非付款。需求与采购冻结通过状态规则实现，未使用无法校验的模拟评估服务。

API服务端执行ALL/DEPARTMENT/SELF，SELF只允许同部门本人参与的通知；导出同样检查。账号选项目录只显示范围内启用人员，指定人员必须来自通知部门。系统仅登记人工证据；实物库存占用、采购审批合同和替代验证仍由真实业务系统及专业人员完成。
